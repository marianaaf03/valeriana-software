# Reglas de trabajo de Valeriana Software

## 1. Organización del equipo

El equipo está conformado por Mariana Alvarez, quien cumple el rol de líder, y Valeria Guevara, quien participa como desarrolladora. Ambas integrantes deben colaborar y revisar los cambios de la otra.

## 2. Nombre de las ramas

Cada tarea debe realizarse en una rama diferente a `main`. Usaremos nombres cortos, en minúsculas y separados por guiones.

Ejemplos:

* `1-readme-empresa`
* `2-reglas-equipo`
* `3-estructura-proyecto`

## 3. Mensajes de los commits

Los commits deben tener mensajes claros que expliquen qué cambio se realizó. Utilizaremos el formato `tipo: descripción`.

Ejemplos:

* `docs: crear el readme de la empresa`
* `feat: agregar una funcionalidad`
* `fix: corregir un error`
* `chore: organizar los archivos`

## 4. Pull Requests

Cuando una integrante termine una tarea, debe subir su rama y abrir un Pull Request hacia `main`. El Pull Request debe explicar los cambios y mencionar el issue relacionado.

## 5. Revisión y aprobación

La otra integrante debe revisar los cambios antes de aprobarlos. Ninguna integrante puede aprobar su propio Pull Request. Se requiere al menos una aprobación para fusionar los cambios.

## 6. Protección de main

La rama `main` está protegida. Los cambios deben entrar mediante Pull Requests aprobados, sin subir directamente a esta rama.

## 7. Trabajo responsable

Cada integrante debe trabajar en las tareas que tiene asignadas, mantener los archivos organizados y avisar si encuentra errores o dificultades.
